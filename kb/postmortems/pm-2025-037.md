# Postmortem: Intermittent 502s from orders OOM restarts

## Summary
An unbounded in-memory cache of order drafts leaked memory in orders. The container was OOMKilled roughly every 18 minutes, producing bursts of 502 errors at the gateway.

## Timeline
- 11:00 orders mem started rising linearly after a feature flag was enabled.
- 11:18 first "Container orders OOMKilled (exit code 137)".
- 11:19 gateway errors spiked, then recovered, then repeated at 11:37.

## Lessons
- Bursty errors that recover on their own suggest restarts; check mem for a sawtooth.
- GC pause warnings on another service at the same time were unrelated.
