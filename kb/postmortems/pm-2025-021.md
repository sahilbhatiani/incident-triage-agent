# Postmortem: Order API timeouts from exhausted connection pool

## Summary
A batch reconciliation job held transactions open, exhausting the postgres connection pool. Payments and inventory queued on "timeout acquiring connection" and orders returned 504s.

## Timeline
- 09:40 db_pool_used reached 100/100.
- 09:41 payments p95 latency rose from 140ms to 2.3s.
- 09:43 gateway alert fired. A simultaneous CPU spike from the inventory report cron misled the first responder for 10 minutes.

## Lessons
- Pool saturation precedes caller latency; check pool metrics before chasing CPU.
- Cron CPU spikes on unrelated services are a recurring red herring.
