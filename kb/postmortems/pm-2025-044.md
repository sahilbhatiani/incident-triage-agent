# Postmortem: Session cache stampede after nightly TTL expiry

## Summary
All session keys were written by the same nightly job with ttl=3600 and expired in one sweep. The redis hit ratio fell from 94% to 9%, misses fell through to postgres, and orders latency tripled.

## Timeline
- 10:00 redis "expired 190k keys in one sweep".
- 10:00 redis cpu and miss rate jumped; postgres rps rose 70% a minute later.
- 10:03 gateway alert fired. Responders first suspected postgres because its load was highest.

## Lessons
- When postgres load rises right after redis misses spike, the cache is the cause.
- Add TTL jitter.
